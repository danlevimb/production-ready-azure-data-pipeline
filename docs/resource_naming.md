# Resource Naming

**Project:** `production-ready-azure-data-pipeline`

---

## 1. Purpose

This document defines the initial resource naming strategy for the MVP.

Names should be clear, short, and safe for Azure naming constraints.

---

## 2. Naming Components

| Component | Meaning | Example |
|---|---|---|
| Project short code | Short project identifier | `prdp` |
| Environment | Environment code | `dev` |
| Suffix | Generated uniqueness suffix | `a1b2c3` |

---

## 3. Resource Names

| Resource | Pattern | Example |
|---|---|---|
| Resource Group | `rg-prdp-dev` | `rg-prdp-dev` |
| Storage Account | generated by Bicep | `stprdpdevxxxxxx` |
| ADLS Container | `datalake` | `datalake` |
| Data Factory | `adf-prdp-dev-<suffix>` | `adf-prdp-dev-a1b2c3` |
| Key Vault | `kv-prdp-dev-<suffix>` | `kv-prdp-dev-a1b2c3` |
| Log Analytics | `law-prdp-dev-<suffix>` | `law-prdp-dev-a1b2c3` |

---

## 4. Naming Principles

- Keep names short.
- Use lowercase where possible.
- Use `dev` for the MVP environment.
- Let Bicep generate uniqueness where global names require it.
- Avoid personal names, emails, or sensitive identifiers.
